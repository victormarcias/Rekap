# Model Comparison

A quick look at the most relevant models today — proprietary (via API) and open-source (self-hosted, see [Ollama](llm-costs.md#beyond-the-api-self-hosted--open-source)) — with no exact per-token prices (that's in [LLM Costs](llm-costs.md) and goes stale fast). Here the focus is **what you get and what you give up** by choosing each one.

| Model | Typical use case | Free / Cost | Average size | Advantages | Cons |
|---|---|---|---|---|---|
| **Claude** (Anthropic) | Code and complex agents in production — coding assistants, multi-step agentic workflows | Paid, per token (API) | Not published (proprietary) | Strong at reasoning and code, aggressive prompt caching, extended thinking ([test-time compute](what-is-a-token.md#test-time-compute--thinking-more-when-answering-not-when-training)) | No self-host option — 100% dependent on the API and its availability |
| **GPT** (OpenAI) | General-purpose chatbots, products with third-party integrations already built around the OpenAI ecosystem | Paid, per token (API) | Not published (proprietary) | Largest ecosystem (tools, plugins, community), good price/quality balance in mid tiers | Same no-self-host issue; big price jump between mid tier and flagship |
| **Gemini** (Google) | Analyzing entire documents/codebases (large context window), products already integrated with Google Workspace/Cloud | Paid, per token (API) | Not published (proprietary) | Largest context window on the market, native integration with the Google stack (Workspace, Cloud) | Less "battle-tested" in production outside the Google ecosystem, compared to Claude/GPT |
| **Llama** (Meta) | Self-hosted prototypes, custom fine-tuning, cases needing full control over the model | Free, self-hosted | 7B – 405B depending on variant | The most adopted of the open-source ecosystem — best tooling support ([Ollama](llm-costs.md#beyond-the-api-self-hosted--open-source) and others), largest community | Quality below proprietary flagships; large variants (70B+) need serious hardware |
| **Mistral** | Self-hosted on limited hardware (laptop, edge, on-device) where Llama doesn't fit comfortably | Free, self-hosted | 7B – 123B depending on variant | Good performance/size ratio — performs well even in small variants, runs on more modest hardware | Fewer variants and fine-tunes available than Llama |
| **Dolphin** (fine-tune) | Research, red teaming, or any case where a censored model legitimately refuses the task | Free, self-hosted | Depends on the base model (a Llama/Mistral fine-tune) | No content restrictions from the base model — [an "uncensored" model](llm-costs.md#open-source-self-hosted-vs-proprietary-llm-api) | Inherits the base model's performance limitations; using it irresponsibly is the runner's responsibility, not the provider's |
| **Ornith** (DeepReinforce) | Agentic coding — autonomous multi-step code tasks (the same kind of task [SWE-Bench](https://www.swebench.com/)/Terminal-Bench measure) | Free, self-hosted (MIT) | 9B – 397B [MoE](model-size-and-quantization.md#dense-vs-moe-mixture-of-experts) (9B-Mobile quantized variant, ~1.5GB) | Self-generated training curriculum (proposes its own tasks, harnesses, and solutions); reported benchmarks near or above Claude Opus in coding | Very recent (Aug 2026) — benchmarks are the vendor's own figures, no independent verification yet; the flagship model (397B) demands the same heavy hardware as a Llama 405B |
| **Grok** (xAI) | Coding/agentic on a tight budget (performs close to a flagship but faster/cheaper), tasks needing real-time X/Twitter data | Paid, per token (API) | Not published — [MoE](model-size-and-quantization.md#dense-vs-moe-mixture-of-experts) architecture, ~1.5T total parameters (Grok 4.5) | Performs close to Claude Opus on its own benchmarks, but faster and more token-efficient; very large context window (up to 2M in some variants); access to real-time data via X | Less production track record than Claude/GPT/Gemini; smaller integration ecosystem; not to be confused with **Groq** (with a Q), which is hardware, not a model — see [Groq and LPUs](model-size-and-quantization.md#groq-and-lpus--specialized-hardware-for-speed) |

**How to read the table**: "Average size" only applies to open-source models, because the parameter count is published (7B = 7 billion) — proprietary providers don't publish that figure, it's part of what they sell as a competitive advantage. How much that takes up in real disk/memory (and why that's not the same as the parameter count) is in [Model Size and Quantization](model-size-and-quantization.md).

**Note on Ornith**: unlike the rest of the table (established models with months/years of production use), Ornith is brand new material — treat it as "a claim to validate," not a settled fact, until independent benchmarks exist.
