# Context Engineering

Deliberately deciding **what goes into the model's context window on every call** — not just what you ask it, but the system prompt, the available tools, the conversation's memory, and documents retrieved via RAG. It's more decisive for an agent's quality, cost, and reliability than which model you pick: an excellent model with messy or irrelevant context performs worse than a smaller one with well-curated context.

## The pieces this discipline already assembles

Context Engineering isn't an isolated concept — it's the umbrella that ties together several pieces already covered separately:

- **The limit**: [Context window](what-is-a-token.md#why-it-matters) — how much context the model can "see" at once.
- **What to send from the history**: [Conversational Memory](conversational-memory.md) — full buffer, sliding window, summarization, vector DB.
- **What to bring in from outside**: [RAG](rag.md) — retrieval + reranking, so you don't stuff in whole documents when the relevant fragments are enough.
- **What to send fixed**: [System prompt structure](prompt-engineering.md#structure-of-a-system-prompt) — role, context, instructions, tools, variables.

## Context Rot

Response quality degrades as context grows — **even without hitting the context window's hard limit**. It's not that the model "fills up" and fails abruptly; it's gradual: with more tokens in the context (especially if there's irrelevant, repeated, or poorly organized information), the model has a harder time prioritizing what's relevant to the current question, and accuracy drops.

**Mitigation**: it's not "add more context just in case" — it's the opposite. Send only what's relevant (the same spirit as RAG's retrieval) and actively clean up what's no longer needed, instead of letting the context grow unchecked.

## Compaction

When a conversation or an agent has gone through many steps and the context is approaching the limit (or has simply grown too large), instead of bluntly cutting history — losing information — it gets **automatically summarized**: the old part gets replaced by a compact summary generated by the model itself, preserving the essentials with far fewer tokens.

It's the same idea as [summarization memory](conversational-memory.md#summarization-memory), but applied to a running agent's entire context, not just the chat history — tools like Claude Code run this automatically when a long session approaches the limit, without the user having to ask for it.

## Practical rule

Relevant, well-organized context always beats large context. Before adding something to the context (an entire document, the full history, every available tool) it's worth asking whether it's needed for **that specific step** — every extra token isn't free (it's paid for, see [LLM Costs](llm-costs.md)) and can actively worsen the response through context rot, not just make it more expensive.
